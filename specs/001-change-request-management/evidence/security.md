# بازبینی امنیت ـ T061

**تاریخ**: 2026-11-17 | **نتیجه**: هر ۱۱ آزمون جدید security-regression.spec.ts و رگرسیون قبلی موفق بودند.

| بررسی | نتیجهٔ واقعی |
| --- | --- |
| JWT با امضا، issuer، audience، انقضا یا subject نامعتبر | 401 و WWW-Authenticate؛ JSON ناسالم بر هویت تقدم نیافت و هیچ داده تغییر نکرد. |
| JWT معتبر بدون نگاشت محلی، حتی با role claim هر دو نقش | ایجاد 403؛ هر پنج عملیات وابسته به شناسه روی منبع موجود و ناموجود، 404 عمومی برابر؛ هیچ user، نقش یا درخواست ساخته نشد. |
| دو نقش و Headerهای جعلی | Approve و RequestChanges روی درخواست خود 403 و بدون تغییر؛ Header انتخابی مشتری مالک را عوض نکرد. |
| role claim قدیمی پس از لغو مجوز | مشاهدهٔ قبلی و توکن قبلی مجوز تصمیم نساختند؛ 404 و بدون تغییر. |
| فراخوانی مستقیم Application بدون Controller | ایجاد توسط Reviewer، ویرایش/Submit غیرمالک و هر دو تصمیم روی درخواست خود رد شدند. |
| خطای واقعیِ تزریق‌شده در Store کاربر | 500 با INTERNAL_ERROR؛ خطای Database به نبود نگاشت 404 تعبیر نشد و متن SQL یا stack افشا نشد. |

آزمون‌ها روی Bootstrap مشترک، JWT واقعی آزمایشی و SQLite فایل‌محور با Migration واقعی اجرا شدند. snapshot کاربران و درخواست‌ها در موارد حساس مقایسه شد. پاسخ‌ها از نظر نشت کلید آزمایش، JWT، SQL، stack و Headerهای غیرمجاز بررسی شدند. رگرسیون محرمانگی با JSON/DTO/If-Match ناسالم و تغییر مجوز یا visibility بین Guard و Application نیز در مجموعه‌های US3 و US5 موفق است.

شاهد: [Integration نهایی](../../../test-results/us8/integration.json)، [Contract نهایی](../../../test-results/us8/contract.json) و [Concurrency نهایی](../../../test-results/us8/concurrency.json). تطبیق Schema خطا و Headerها در openapi-contract.spec.ts نیز اجرا شد. شواهد فوق آزمون نفوذ جامع یا ممیزی کامل زنجیرهٔ وابستگی نیستند؛ ابزار npm در نصب دربارهٔ glob@10.5.0 غیرمستقیم هشدار داد و رفع آن ادعا نشده است. راهبرد هویت همچنان فقط Development/Test است و برای production تأیید نشده است.

Ajv 8.20.0 که قبلاً در درخت وابستگی وجود داشت، برای اعتبارسنجی استاندارد Schemaهای OpenAPI به devDependencies مستقیم اضافه و قفل شد؛ هیچ وابستگی Runtime یا تصمیم امنیت محصول تغییر نکرد.
